# v1.0.0 release report

> **Status:** release prepared on 2026-11-19, deployed on 2026-11-21. The version, CI/CD workflows and hosting configuration are in place, and `main` with the `v1.0.0` tag exists. Two credential problems blocked the first attempts: the workflow used a service account without permission on the project (`FIREBASE_SERVICE_ACCOUNT`), then the correct account lacked `roles/firebaserules.admin`. Both are fixed — the workflows accept either secret name and validate it ([Decision 0026](/decisions/0026-firebase-credentials-and-workflow-consolidation.md)), and the role was granted. `Deploy` run `44953688196` succeeded: `firestore.rules` then Hosting `live`. `https://alessandrotorri-it.web.app` serves the app; `www.alessandrotorri.it` still points at Adobe Portfolio.

## Delivered capabilities

- **Public site.** React 19 + Vite 8 + MUI 9 + Zustand + Firebase. Shared gallery grid at `/` and `/gallery`, Masonry feed and keyboard lightbox at `/gallery/:slug`, responsive layout, SEO metadata, sitemap, lazy routes and error boundary.
- **Gallery model.** Firestore `galleries` with ordered `imageIds`, `coverImageId` + denormalized `coverImageUrl`, `isVisible`, `isFeatured`/`featuredOrder`, and `layoutConfig` (`aspectRatio`, photo `padding`, `coverSpacing`).
- **Image catalog.** Firestore `images` with `filename`, `path`, title/description/alt, `aspectRatio`, `isVisible` and `galleryIds`; GitHub contents discovery of `public/galleries/`; `/admin/images` filters, inline edits, assignment, detach and bulk indexing.
- **Presentation.** Photo ratios win in the feed with the gallery ratio as fallback; covers are chosen from the gallery's own photos; one featured gallery renders as a compact full-width banner, two or more as a half-width pair; a solid `LUOGHI` divider separates the featured block; the footer shows only the copyright; the logotype is serif uppercase.
- **Admin.** Protected routes, `admins/{uid}` allowlist, Firestore diagnostics and preflight, one edit path (`/admin/gallery/:id`), drag-and-drop ordering, cover selection, visibility and layout controls.
- **Data safety.** Public reads with a cached join and static CDN fallback on failure/empty; every membership change keeps `imageIds` and `galleryIds` in sync; hidden or empty galleries are filtered from the public site.
