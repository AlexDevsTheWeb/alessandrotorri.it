# Summary

Issue #2 covers phases 3–5 of the public rebuild. This loop implements all three: the 9-cover gallery grid, the Masonry collection feed with lightbox, and the SEO/performance polish.

# Phase 3 outcome

- New `src/components/CollectionGrid.component.tsx` — responsive `Grid` (`xs: 12`, `sm: 6`) over `COLLECTIONS`.
- New `src/components/CollectionCover.component.tsx` — 16:9 `ProgressiveImage`, centered uppercase title inside the cover, gradient overlay, no entrance animation (later refined by [decision 0008](/decisions/0008-visual-refinements.md)).
- `GalleryPage` now renders `CollectionGrid`; the "Explore the Collections" heading and demo `PhotoGallery` usage are gone.
- `HomePage` renders the same `CollectionGrid` directly, matching the live site where `/` is the gallery ([decision 0007](/decisions/0007-home-gallery-grid.md)). The Unsplash hero, commented Firestore blocks, and `height: 3000px` hack are removed.
- Deleted the dead `src/components/Navbar.tsx`.

# Phase 4 outcome

- All 9 collection photo lists were captured from the live site: **89 photos** with real CDN URLs, Italian captions and aspect ratios, in `src/data/collections.photos.ts`. The favorite collection has its full 24.
- `CollectionPage` now reads the slug with `useParams`, looks up `COLLECTIONS` and `PHOTOS`, and no longer queries Firestore.
- Masonry feed at `maxWidth="lg"` (1 / 2 / 3 columns), centered uppercase H1.
- Desktop breadcrumb in the navbar (`Gallerie / {title}`), hidden on mobile; the page no longer renders a breadcrumb, and the H1 remains the title ([decision 0010](/decisions/0010-navbar-breadcrumb.md)).
- Image captions are hidden by default and revealed on hover/focus: a ~50% black gradient fades in while the caption slides up to the center.
- MUI Masonry's negative root margin is neutralized so the mobile single column has equal left/right gutters (24px at 390px).
- Each photo is a keyboard-accessible button wrapping `ProgressiveImage`; the lightbox still shows the caption.
- New `PhotoLightbox` component: fullscreen dark `Dialog`, blurred backdrop, image at up to 75vh, caption + “Dati EXIF non disponibili”, prev/next, Esc/arrow keys, side arrows on desktop, arrows below on mobile.
- `ProgressiveImage` now accepts an optional placeholder, so feed images can load without a synthetic blur asset.

# Phase 5 outcome

- `index.html` has correct default Italian title, description, canonical, OG and Twitter tags; the `%VITE_APP_SITE_TITLE%` placeholder is gone.
- `usePageMeta` sets per-route title/description/canonical/OG/Twitter; collection pages use the cover and photo count.
- `public/robots.txt` and `public/sitemap.xml` cover the home, gallery and 9 collection routes.
- Routes are lazy-loaded; `SharedLayout` wraps the outlet in `Suspense` + `ErrorBoundary`.
- `vite.config.ts` splits React, MUI/Emotion and Firebase chunks; `firebase.ts` is auth-only and `firebaseData.ts` loads Firestore/Storage with admin.
- The dead `PhotoGallery` demo and unused `framer-motion` dependency were removed.
- First feed image is eager/high-priority with a 600w/1200w `srcset`; other images stay lazy.
- Responsive checks at 390 / 768 / 1280: no horizontal overflow, 1/2/3 Masonry columns, breadcrumb hidden on mobile, lightbox scroll lock and arrow keys verified.

# Verification

- `npm run lint` — clean.
- `npm run build` — succeeds, no chunk over 500 kB.
- `/gallery/01-favorite` resolves 24 photos with real captions.
- Meta/canonical verified for `/`, `/gallery`, `/gallery/07-francia`.
- `PhotoLightbox` opens, advances with ArrowRight, closes with Escape, and locks body scroll.
- Lighthouse local preview: accessibility 100, best practices 100, SEO 100, performance 74 (LCP dominated by a 6.7s local TTFB); deployment verification is issue #14.
