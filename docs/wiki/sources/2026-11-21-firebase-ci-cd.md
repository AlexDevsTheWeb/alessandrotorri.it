# 2026-11-21 — Firebase Hosting and CI/CD fix

## What the source asks

1. Consolidate `.github/workflows/`: delete the `firebase-hosting-merge.yml` / `firebase-hosting-pull-request.yml` files generated by `firebase init` and keep exactly `ci.yml` (PRs to `development`/`main`) and `deploy.yml` (`main` and `v*` tags), both with Node 22, `npm ci`, lint, `tsc -b`, build, a Hosting deploy to `live` and a Firestore rules deploy.
2. Audit `firebase.json` (`hosting.public: dist`, SPA rewrite, `firestore.rules`) and `.firebaserc` (`default: alessandrotorri-it`).
3. Accept `FIREBASE_SERVICE_ACCOUNT` or `FIREBASE_SERVICE_ACCOUNT_ALESSANDROTORRI_IT` in `deploy.yml`, with explicit `projectId` and `channelId: live`.
4. Verify lint, `tsc -b`, build and workflow YAML.
5. Write `IMPLEMENTATION_PLAN.md`, commit to `development`, summarize the changed files.

The stated diagnosis is that `firebase init` left duplicate workflows, that Hosting pointed at `public`, and that concurrent workflows caused the "Site not found" page.

## Findings (verified against the repository and GitHub)

- **No duplicate workflows on `development`.** `.github/workflows/` holds `ci.yml`, `preview.yml` and `deploy.yml`. The generated files live on `main` only: commit `df2aea2` ("fix: set firebase hosting public directory to dist", 2026-11-21 22:25 CET), the single commit by which `main` is ahead of `development`. It also added `public/index.html` (the Firebase welcome placeholder) and `skills-lock.json`, and touched `.gitignore`.
- **`firebase.json` and `.firebaserc` already match the requested content.** `hosting.public` is `dist` and the SPA rewrite is present; the default project is `alessandrotorri-it`.
- **The deploy failure is a credential problem, not a build problem.** `Deploy` runs `44881900532` (`main`), `44881947876` (tag `v1.0.0`) and `44951483231` (`main`) all fail at **Deploy Firestore rules** with:

  ```text
  Error: Request to https://serviceusage.googleapis.com/v1/projects/alessandrotorri-it/services/firestore.googleapis.com
  had HTTP Error: 403, Permission denied to get service [firestore.googleapis.com]
  ```

  The hosting step never runs, so nothing is ever published to the `live` channel and `<project>.web.app` answers "Site not found".
- **Two secrets exist.** `FIREBASE_SERVICE_ACCOUNT` (created 2026-11-21T07:41Z) is the one every failed run used; `FIREBASE_SERVICE_ACCOUNT_ALESSANDROTORRI_IT` (created 2026-11-21T21:16Z) was written by `firebase init` for this project.
- **`public/index.html` does not break the build.** Tested locally: with the placeholder in `public/`, `vite build` still emits the application `dist/index.html` (Vite's generated entry wins). The file is inert junk on `main`, not the cause of the outage.
- `ci.yml` runs on pushes to `development`/`main` and on **every** pull request; `preview.yml` is already limited to PRs targeting `development`/`main`.

## What changed

- `deploy.yml`: one job-level credential resolved as `secrets.FIREBASE_SERVICE_ACCOUNT_ALESSANDROTORRI_IT || secrets.FIREBASE_SERVICE_ACCOUNT`; the credential is validated before use (non-empty, valid JSON, `client_email` and `private_key` present) and a warning is printed when the key's `project_id` differs from the target; `FIREBASE_PROJECT_ID` keeps the `alessandrotorri-it` default; rules first, then Hosting `live`.
- `preview.yml`: same credential resolution and project id; the skip message names both secrets.
- `ci.yml`: pull requests limited to `development`/`main`.

## Verification

- `npm run lint` and `npm run build` pass; all three workflows parse as YAML and `firebase.json`/`.firebaserc` parse as JSON.
- PR #28's `Preview` workflow deployed `https://alessandrotorri-it--preview-28-9v0hpxcr.web.app` with `FIREBASE_SERVICE_ACCOUNT_ALESSANDROTORRI_IT`: the channel returns `200` with the application title, serves the hashed assets and answers the `/gallery` deep link through the SPA rewrite. This proves the credential works and the Hosting site exists, so "Site not found" comes from the absent live release.
- Not executed: `Deploy` itself (it needs the merge to `main`).
