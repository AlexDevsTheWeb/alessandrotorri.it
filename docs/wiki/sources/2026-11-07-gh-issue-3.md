# Summary

Issue #3 says the administrator section exists but is not protected: `ProtectedRoute` is not applied, so `/admin` and `/admin/collection/:name` are publicly reachable. The checklist asks to re-enable the guard, verify the redirect when signed out, confirm the Firestore and Storage rules match admin-only access, and update the admin wiki page and log.

# Analysis

- `ProtectedRoute` existed but was not imported in `App.tsx`.
- Auth resolves asynchronously; the guard needs an `isAuthReady` flag or a refreshed `/admin` would redirect before auth loads.
- No `firestore.rules` or `storage.rules` existed in the repository, so "match admin-only access" could not be confirmed. Rules are added in this change.
- The owner's admin UID is not known to the repository, so access is granted by an `admins/{uid}` document created in the console.

# Decision

[0014 — Protect admin routes and gate data with an admins allowlist](/decisions/0014-admin-route-protection.md).

- Not verified: rules in the emulator or the live project; signed-in admin flow.
