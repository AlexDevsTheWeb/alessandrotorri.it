## 1. Analysis

The first production deploys failed. The source blames duplicate `firebase init` workflows, a Hosting directory pointing at `public`, and concurrent runs.

Verified facts:

- `.github/workflows/` on `development` holds only `ci.yml`, `preview.yml` and `deploy.yml`. No duplicate workflows.
- The generated files live on `main` only, in commit `df2aea2` (single commit ahead of `development`): `firebase-hosting-pull-request.yml`, `public/index.html`, `skills-lock.json`.
- `firebase.json` already uses `hosting.public: dist` with the SPA rewrite; `.firebaserc` already pins `alessandrotorri-it`.
- `Deploy` runs `44881900532`, `44881947876` (tag `v1.0.0`) and `44951483231` all fail at **Deploy Firestore rules** with `403 Permission denied to get service [firestore.googleapis.com]`; the Hosting step never runs.
- Two secrets exist: `FIREBASE_SERVICE_ACCOUNT` (used by the failing runs) and `FIREBASE_SERVICE_ACCOUNT_ALESSANDROTORRI_IT` (generated by `firebase init`).
- `public/index.html` does not overwrite `dist/index.html`; Vite's generated entry wins (verified locally with a build).

### Contradictions and resolutions

| Contradiction | Resolution |
|---------------|------------|
| "Duplicate workflows conflict." | None on `development`. The generated files are removed on `main` in a separate commit, since a PR into `development` cannot delete files that branch never had. |
| "Hosting pointed at `public`." | Not true: `firebase.json` maps `dist`. `public/` only holds static assets copied into `dist`. |
| "Concurrent workflows caused incomplete uploads." | Not true: `deploy.yml` has a `cancel-in-progress: false` concurrency group; the runs fail on a credential `403` before any upload. |
| The source asks for `IMPLEMENTATION_PLAN.md`. | This file is updated; the plan of record stays in the wiki. |
| The source asks to commit to `development`. | AGENTS §7: branch plus PR into `development`. |
| The source asks to keep only `ci.yml` and `deploy.yml`. | `preview.yml` is deliberate ([Decision 0025](docs/wiki/decisions/0025-release-v1-and-ci-cd.md)) and is kept; still exactly three workflows, no generated ones. |

### Requirements and acceptance criteria

- `deploy.yml` and `preview.yml` accept either secret name, project-specific first.
- Credential validated before deploying (non-empty, JSON, `client_email`/`private_key`); project mismatch warning.
- Explicit `projectId` and `channelId: live`.
- Rules deployed before Hosting.
- `ci.yml` pull requests limited to `development`/`main`.
- Wiki: source summary, decision 0026, playbook, overview, rebuild plan, release report, indexes and log.
- `npm run lint`, `npm run build`, workflow YAML valid.

Out of scope: executing the deploy, creating or deleting Firebase resources, editing `docs/raw/`, editing history on `main`.

## 2. Deploy flow

```text
push to main / tag v*  →  Deploy
                            ├─ npm ci, lint, typecheck, build
                            ├─ validate credential (either secret)
                            ├─ firestore.rules
                            └─ Firebase Hosting → live
```

## 5. Post-merge checklist

1. Merge this PR into `development`.
2. On `main`, remove `firebase-hosting-pull-request.yml`, `public/index.html` and `skills-lock.json` (from `df2aea2`); keep `firebase.json` with its `dist` target.
3. Re-run `deploy.yml` (`workflow_dispatch`) or push a new tag; confirm the rules deploy succeeds with `FIREBASE_SERVICE_ACCOUNT_ALESSANDROTORRI_IT`.
4. If Hosting reports `Site not found`, create the default site: `firebase hosting:sites:create alessandrotorri-it`.
5. Smoke-test `/`, `/gallery`, `/gallery/<slug>`, `/login`, `/admin`, `/admin/images` on desktop and 390 px.
6. Fix or delete `FIREBASE_SERVICE_ACCOUNT` so the precedence is no longer ambiguous.

## 6. Risks

- The credential precedence is implicit while both secrets exist.
- The `main` cleanup is manual and not enforced by CI.
- The Hosting site may still need to be provisioned in the Firebase project.
- A rules failure still blocks hosting by design; the message now names the credential problem instead of only the 403.
